# Jekyll + Tailwind CSS Starter

A starter setup for building static websites with **Jekyll** for pages, layouts, and content, and **Tailwind CSS v4** for styling.

The goal is to create a reusable foundation for multiple websites that share functionality but can have very different visual designs.

## 1. Create the Jekyll site

Make sure Ruby, Bundler, Node.js, and npm are installed.

```bash
mkdir my-website
cd my-website

git init

gem install jekyll bundler
jekyll new . --force
```

The `--force` flag lets Jekyll generate its starter files inside the existing Git repository.

Start the site to verify Jekyll works:

```bash
bundle exec jekyll serve
```

Open <http://localhost:4000>. Stop the server with `Ctrl+C` before continuing.

## 2. Install Tailwind CSS

Initialize npm and install Tailwind v4's CLI:

```bash
npm init -y
npm install -D tailwindcss @tailwindcss/cli
```

This setup uses Tailwind's CLI directly; no JavaScript framework such as React is required.

## 3. Create the Tailwind input file

Create `src/tailwind.css`:

```css
@import "tailwindcss";

@source "../";
```

The `@source` directive tells Tailwind to scan the project for class names in Jekyll templates and content.

A simplified project structure will look like this:

```text
my-website/
├── _includes/
├── _layouts/
├── _posts/
├── assets/
│   └── css/
├── src/
│   └── tailwind.css
├── _config.yml
├── Gemfile
├── package.json
└── index.md
```

Keep any additional files generated by Jekyll.

## 4. Add npm build scripts

In `package.json`, add these entries inside the existing `"scripts"` object:

```json
"css:watch": "tailwindcss -i ./src/tailwind.css -o ./assets/css/tailwind.css --watch",
"css:build": "tailwindcss -i ./src/tailwind.css -o ./assets/css/tailwind.css --minify"
```

Keep any other scripts that are already there.

- `css:watch` rebuilds the stylesheet as you work.
- `css:build` generates a minified stylesheet for production.

## 5. Connect Tailwind to Jekyll

Open `_layouts/default.html` and add this stylesheet link inside the HTML `<head>`:

```liquid
<link rel="stylesheet" href="{{ '/assets/css/tailwind.css' | relative_url }}">
```

The `relative_url` filter helps Jekyll generate the correct URL when deploying to a subpath, such as a GitHub Pages project site.

Test Tailwind by adding this to a page:

```html
<h1 class="text-4xl font-bold text-blue-600">
  Hello, Tailwind!
</h1>
```

If the heading appears large, bold, and blue, the integration is working.

> If you're using a Jekyll theme, check its existing stylesheet references. Remove or adjust conflicting styles if you want Tailwind to control the design.

## 6. Run both development processes

Use two terminal tabs, both opened in the project directory.

### Terminal 1: Tailwind

```bash
npm run css:watch
```

This compiles the CSS whenever your source files change.

### Terminal 2: Jekyll

```bash
bundle exec jekyll serve --livereload
```

This serves the site and refreshes the browser when supported changes are detected.

Visit <http://localhost:4000>.

## 7. Add a `.gitignore`

Make sure `.gitignore` contains at least:

```gitignore
_site/
.sass-cache/
.jekyll-cache/
.jekyll-metadata
node_modules/
```

Commit the starter project:

```bash
git add .
git commit -m "Set up Jekyll and Tailwind CSS"
```

Keep `Gemfile.lock` and `package-lock.json` in Git so dependencies can be reproduced consistently.

## 8. Build for production

When you're ready to deploy:

```bash
npm run css:build
bundle exec jekyll build
```

The generated static website will be in `_site/`. Configure your hosting service to publish that directory.
